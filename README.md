##Призначення скрипта:

Скрипт відповідає за зчитування дій гравця через нову систему вводу Unity Input System та обробку фізичного руху персонажа на сцені.

Ключові елементи коду:

public InputAction MoveAction; — оголошує дію руху типу Vector2. Це дозволяє гнучко налаштовувати клавіші керування (WASD, стрілочки) безпосередньо через Inspector без зміни коду.

MoveAction.Enable(); — вмикає відстеження натискань клавіш під час запуску гри у методі Start().

MoveAction.ReadValue<Vector2>(); — у кожному кадрі (Update) зчитує поточний напрямок руху. Композити дій автоматично нормалізують вектор за діагональною траєкторією (до значень близько 0.71, 0.71), запобігаючи прискоренню персонажа при одночасному натисканні двох клавіш.

FixedUpdate() та rigidbody2d.MovePosition() — переміщення об'єкта виконується у фіксованому фізичному циклі. Множення на Time.fixedDeltaTime гарантує плавний рух із постійною швидкістю (speed), яка не залежить від частоти кадрів (FPS) на різних пристроях.

**Що не вийшло або забрало найбільше часу:**
- Найбільше часу забрало налаштування колайдерів тайлмапа: спочатку персонаж проходив крізь воду, оскільки на об'єкті `Tilemap` не було `Tilemap Collider 2D` та `Composite Collider 2D`. Також довелося усувати помилки компіляції через відсутні змінні здоров'я.

**Що зрозумів про FixedUpdate і колайдери:**
- `Update()` зчитує натискання клавіш щокадру, а `FixedUpdate()` виконує фізичні обчислення у такт рушію (50 разів на секунду).
- Переміщення через `transform.position` викликало тремтіння біля стін, бо телепортувало об'єкт в обхід фізики. `MovePosition()` вирішує це, перевіряючи колізії перед рухом.
- Якщо тайлам підлоги не поставити `Collider Type = None`, персонаж застрягне на місці, бо підлога стане суцільною перешкодою.
- `Composite Collider 2D` об'єднує сітку колайдерів води в один контур, щоб персонаж не застрягав на стиках окремих плиток.

**Що в рівні вийшло не так, як у фізичному паспорті, і чому:**
- Початкова карта вийшла трохи компактнішою, ніж у плануванні, щоб швидше протестувати взаємодію з колайдерами та сортування за Y, але всі зони (підлога, берег, вода) працюють за паспортом.

### 28.10.2026 - Юніт 4: Вороги та Снаряди

### Що зроблено:
- Створено та налаштовано механіку патрулювання ворога (`EnemyController`) з можливістю перемикання напрямку (вертикально/горизонтально).
- Реалізовано систему запуску снарядів (`Projectile`) гравцем `PlayerController` на клавішу `C`.
- Налаштовано обробку зіткнень (Triggers) та механіку "полагодження" ворога (`Fix()`) при влучанні снаряда.
- Оптимізовано систему здоров'я гравця та невразливість після отримання шкоди.

### Де застрягли та як вирішили:
1. **Зникнення та застрягання снаряда при появі:** Снаряд з'являвся всередині колайдера гравця та миттєво знищувався через тригерні зони. Вирішено через ігнорування `PlayerController` та зон-тригерів у коді `Projectile.cs`.
2. **Снаряд стояв на місці при пострілі:** Причина була у використанні `Start()` замість `Awake()` для отримання компонента `Rigidbody2D`, через що сила `AddForce` застосовувалася до неініціалізованого компонента.
3. **Виліт ворога за карту:** Початкові налаштування швидкості та часу патрулювання вибивали ворога за межі сцени.

### Що зрозуміли під час розробки:
- **`Awake()` vs `Start()`:** `Awake()` викликається в момент створення об'єкта (`Instantiate`), що критично для снарядів, оскільки метод `Launch()` викликається в тому ж кадрі. `Start()` спрацьовує пізніше і не підходить для миттєвої фізичної ініціалізації.
- **Animator:** Важливість вимкнення `Apply Root Motion`, щоб анімація руху не зсувала фізичну позицію `Transform` об'єкта.
- **Шари (Layers) та Colliders:** Використання прапорця `Is Trigger` дозволяє снаряду проходити крізь гравця, реєструючи влучання у ворога чи стіни без фізичного поштовху чи зсуву.

### Налаштування руху ворога:
- **`Speed`** = `2.0`
- **`Change Time`** = `1.5` сек
- *Обґрунтування:* Ці значення обрані для того, щоб ворог патрулював у комфортному для гравця ритмі та не виходив за межі ігрової локації.

### Снаряд та сюжетна рамка:
Наш робот-головний герой не знищує ворогів, а вистрілює деталями/гвинтами для їх "ремонту". При влучанні снаряд викликає метод `Fix()`, після чого робот-ворог заспокоюється, перестає завдавати шкоди й стає дружнім, що повністю відповідає світлій концепції гри про відновлення зламаних механізмів.
